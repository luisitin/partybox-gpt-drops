# B18 - Tiny spring + easing library

`motion.ts` is the complete runtime: zero imports, zero runtime dependencies,
no clock, no randomness, no timers, and no shared simulation state. The public
functions are pure. The gzip gate is **1,200 bytes**, including the gzip wrapper,
for both the actual TypeScript source and its emitted JavaScript (gzip level 9).
TypeScript 5.8.3 is a development-only dependency.

**Verification limitation:** the numerical algorithms are different, but they
were authored by one assistant. This is not a blinded, independently authored
implementation exercise. See `VERIFY.md` -> `UNVERIFIED` before treating this
as satisfying every requested process requirement.

## Use

```ts
import { spring, settleTime, cubicBezier, easings } from './motion.js';

const start = 120, target = 300, seconds = 0.4;
const [offset, velocity] = spring(seconds, 1, 170, 26, start - target, 0);
const position = target + offset;
const duration = settleTime(1, 170, 26, start - target, 0, 0.001);
const eased = easings['ease-in-out'](0.4);
const overshoot = cubicBezier(0.4, 0.3, -0.5, 0.7, 1.5);
// Number.MAX_VALUE is a sentinel, NOT a duration to pass to a timer.
```

For the emitted package, import from `./dist/motion.js` after `npm run build`.
Copying `motion.ts` into an existing TypeScript project requires no package
installation. Declarations are generated by the build.

| API | Result |
| --- | --- |
| `spring(t, mass, stiffness, damping, x0=1, v0=0)` | `[displacement, velocity]` about equilibrium zero |
| `settleTime(mass, stiffness, damping, x0=1, v0=0, epsilon=0.001)` | Conservative time for both absolute displacement and absolute velocity to remain within epsilon |
| `cubicBezier(progress, x1, y1, x2, y2)` | CSS cubic-Bezier easing for valid control points, including endpoint extrapolation |
| `easings.ease`, `easings['ease-in']`, `easings['ease-out']`, `easings['ease-in-out']` | Named easing functions |

Time is in seconds; velocity is displacement units per second. The one epsilon
is a numeric threshold applied to each of those two quantities in the chosen
units. This is an unforced spring, not an integrator with mutable internal state.

## Explicit guards and numeric limits

For `spring`, nonpositive mass, negative stiffness, or negative damping disables
the spring and returns `[0, 0]`, even at t=0. For a valid spring, t<=0 returns the
initial state. Zero stiffness is supported, including a freely moving particle
when damping is also zero. A zero-mass spring is not silently reinterpreted as a
small positive-mass spring.

For `settleTime`, a disabled spring or exactly zero initial state returns zero.
Otherwise, nonpositive tolerance, zero stiffness, zero damping, or an
unrepresentable bound returns `Number.MAX_VALUE`. This sentinel means **no finite
bound was supplied**, not a proof that a particular trajectory can never be
within tolerance. In particular, some zero-stiffness special cases already rest.

For `cubicBezier`, x controls must be in [0,1]. CSS would reject invalid controls;
this numeric API instead supplies the identity fallback. Valid y controls are
not clamped: overshoot is retained. At progress 0 and 1 the endpoints are exact.
The four named curves and the extrapolation rule follow W3C CSS Easing Level 1
(`SOURCES.md`, S1).

Every numeric public return is either a finite literal/sentinel, an explicitly
finite-checked time, or passes through `F`: NaN maps to zero and infinities are
saturated to +/-Number.MAX_VALUE. These guards ensure finite *outputs*, not
accurate physics after an intermediate overflow, underflow, or an unrepresentable
phase. The tested accuracy domain below must not be confused with the much
larger finite-input safety domain. Ordinary built-in JavaScript Math/Number
semantics are assumed; monkey-patched built-ins are outside the contract.

## Algorithm and settling bound

The equation is `mass*x'' + damping*x' + stiffness*x = 0` (S2).
Write `a=damping/(2*mass)`, `w=stiffness/mass`, and `d=a*a-w`.

For d<=0, use `q=sqrt(-d)`, `Z=exp(-a*t)*cos(q*t)` and
`S=exp(-a*t)*sin(q*t)/q`. At q=0, the exact limit is `S=t*exp(-a*t)`.
Then `x=x0*Z+(v0+a*x0)*S` and `v=v0*Z-(a*v0+w*x0)*S`.
This handles underdamping, critical damping, and the undamped/free limits.

For d>0, use `q=sqrt(d)`, slow root `r=-w/(a+q)`, fast root `f=-(a+q)`,
`E=exp(r*t)`, and `S=E*(-expm1(-2*q*t))/(2*q)`. With `b=v0-r*x0`,
`x=x0*E+b*S` and `v=r*x0*E+b*(r*S+exp(f*t))`.
The slow-root quotient avoids subtracting nearly equal roots; `expm1` avoids
cancellation near critical damping. No overflowing cosh/sinh product is used.

For positive stiffness and damping let `rho=a` under/at critical damping, or
`rho=w/(a+sqrt(d))` when overdamped. Define:

```
A = max(abs(x0), abs(v0))
B = max(abs(v0+a*x0), abs(a*v0+w*x0))
C = A + 2*B/(e*rho)
T = max(0, 2/rho * (log(C)-log(epsilon)))
```

In real arithmetic the displacement and velocity magnitudes are bounded by
`(A+B*t)*exp(-rho*t)`. Since `t*exp(-rho*t/2) <= 2/(e*rho)`, each is at most
`C*exp(-rho*t/2)`. Thus T is a conservative all-future-time estimate, not the
first crossing or exact minimum settling time. The estimate intentionally favors
not stopping early. Floating-point tail checks accompany this derivation.

The Bezier solver maintains a bracket on the curve parameter. It allows up to
8 safeguarded Newton steps, falling back to bisection, and performs 64 iterations
overall. It never stops merely because an x residual looks small. Residuals use
endpoint reflection and a centered polynomial near the stationary interior case
`x1=1,x2=0`; this avoids losing the tiny residual by subtracting two values near
one half. Outputs are evaluated in Bernstein form. The reference does not use
this inversion code or residual polynomial.

## Reproduce every test

Use Linux on a little-endian machine, Node 22+, GNU g++ with `__float128` and
libquadmath, and npm. The runtime has no native requirement; these are test tools.

```sh
cd jobs/B18-motion-ts
npm ci --ignore-scripts
npm test
```

`npm test` executes **all suites with seeds 1, 2, and 3**, including all 25
isolated mutations each time. There is no reduced-count test mode or hidden skip.
To repeat one complete seed: `node tests/run.mjs --seed 1` (or 2 or 3).
It verifies the delivered checksums first, compiles strict TypeScript, compiles
the C++ reference, then runs the numerical, property, safety, and mutation gates.
An assertion, compiler error, checksum mismatch, or surviving mutant fails the
command. Compiler/import errors do not count as successful mutant kills.

The committed `results/seed*.json` files are measured snapshots. New runs write
`.work/results/seed*.json`, leaving those snapshots and the checksum manifest
unchanged. The C++ reference streams its corpus through a pipe; its large output
is never shipped or written to a single fixture file. Full corpora are generated
again, not replaced by the recorded maxima or digest.

`../../.github/workflows/B18.yml` is the only file outside this job folder. It
uses the required pull-request path filter, read-only permissions, an Ubuntu
runner, a 30-minute timeout, and only actions/* pinned to major versions. It runs
`npm ci --ignore-scripts` and `npm test`, then uploads the freshly produced JSON.
The PR description is the location for the observed hosted run link.

## Contents and measurement domains

`motion.ts` is production. `tests/reference.ts` supplies RK4, a scaling/squaring
matrix exponential, and a separate settling-bound bisection. `tests/oracle.cpp`
supplies 113-bit de Casteljau + bisection. `tests/exact.mjs` supplies an additional
exact-integer Q160 Bernstein audit. `tests/regressions.mjs` holds fixed cases and
25 source mutations. `tests/run.mjs` runs everything. `VERIFY.md` records counts,
errors, commands and limitations. `SOURCES.md` identifies the external facts.
`SHA256SUMS.txt` covers every delivered file except itself, including the workflow.
All delivered files are below 30 MB; no joining or fixture download is required.

Each seed tests 10,000 springs with mass in [0.1,10), natural angular frequency
in [0.2,40] rad/s, damping ratio in [0,4), initial x and v in [-5,5), and 100 to
10,000 integration steps. Exact-critical cases use mass 1 and integer frequencies
1..40. Near-critical cases perturb the ratio by 1e-6 down to 1e-14. The maximum
error is checked at **every 1e-4-second frame**, for both x and v, not just at the
final sample. Each spring also gets a separate matrix-exponential comparison.

Each seed tests 1,000,000 Bezier inputs. Controls x are in [0,1]; random y are
in [-4,4). Strata include flat endpoints, exact/nearly flat interiors, identical
x controls, named curves, exact progress endpoints, tiny progress increments,
and extrapolation with progress in [-2,3). The near-flat interior stratum targets
the midpoint with x controls within 1e-12 of (1,0). All million outputs are
compared to the 113-bit reference to absolute error <1e-7. Another 40,004 points
check the named exports, and 5,000 independently audit the reference with exact
integer arithmetic. No universal 1e-7 absolute-error claim is made for arbitrary
astronomical y values.
